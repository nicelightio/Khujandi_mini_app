Техническое задание (ТЗ) для проекта Khujandi Mini App
====================================================

1. Общая цель проекта
---------------------
Разработать backend- и frontend-части мини-приложения для Telegram, предназначенного для автоматизации заказов,
 доставки и управления магазинами, клиентами, курьерами и администраторами. 
 Приложение должно быть масштабируемым, асинхронным, 
 с четкой архитектурой и покрытием всех бизнес-процессов, 
 связанных с заказами, пользователями и магазинами.

2. Основные сущности и их атрибуты
----------------------------------
- **Клиент (Client):**
  - telegram_id, name, username, photo_url, language, registered_at, is_vip, reputation, purchase_count, cancelled_count, last_purchase_at, last_purchase_price, last_shop_id, last_shop_name, total_spent, current_order_status, negative_feedback_count, last_negative_feedback, last_negative_feedback_date
- **Курьер (Courier):**
  - telegram_id, name, username, photo_url, is_available, language, registered_at, is_vip, reputation, delivery_count, cancelled_count, last_delivery_at, last_delivery_price, last_shop_id, last_shop_name, last_product_price, total_earned, current_delivery_status, negative_feedback_count, last_negative_feedback, last_negative_feedback_date
- **Админ (Admin):**
  - telegram_id, name, username, photo_url, is_available, language, registered_at, reputation, role, can_edit, negative_feedback, negative_feedback_reason, negative_feedback_date
- **Магазин (Shop):**
  - name, owner_id, is_vip, created_at
- **Товар (Product):**
  - shop_id, name, description, price, is_available, created_at
- **Заказ (Order):**
  - shop_id, shop_name, seller_id, courier_id, client_id, is_vip_client, is_vip_seller, is_vip_courier, is_vip_shop, purchase_price, delivery_price, client_rating, courier_rating, courier_comment, courier_comment_date, client_comment, client_comment_date, status, items, created_at, updated_at

3. Основные бизнес-процессы
---------------------------
- Регистрация и управление пользователями (клиенты, курьеры, админы)
- Создание, просмотр, обновление и удаление заказов
- Управление магазинами и товарами
- Назначение курьеров на заказы
- Оценка и обратная связь по заказам
- Управление статусами заказов и доставок
- Ведение истории заказов, доставок, отзывов

4. Требования к backend (FastAPI)
---------------------------------
- Использовать FastAPI, Pydantic v2, SQLAlchemy 2.0, asyncpg
- Асинхронные CRUD-операции для всех сущностей
- Четкая модульная структура: models, db, routers, utils
- Использовать lifespan-контекст для инициализации ресурсов
- Валидация входных/выходных данных через Pydantic
- Использовать Depends для DI и работы с сессиями БД
- Обработка ошибок через HTTPException и middleware
- Логирование и healthcheck endpoint
- Документация OpenAPI (Swagger)
- postgresql db -- khujandi --  khujandi_db_writer -- HeavypostgresqlpassworD.1

4.1 Архитектура telegram bot aiogram3 
    - Выделен модуль aiobot/ (bot.py, notifications.py, handlers.py).
    - Конфигурирование через config.py (TG_TOKEN, ADMIN_IDS).
    - Инициализация aiogram3 Bot и Dispatcher в aiobot/bot.py.
    - Функции отправки уведомлений (send_order_notification, send_error_notification) в aiobot/notifications.py.
    - Вызов уведомлений из бизнес-логики (core/services/...).
    - Lifespan FastAPI: запуск Dispatcher в фоне через startup/lifespan.
    - Асинхронность, DI, тестируемость, безопасность (секреты через env).
    - Возможность масштабирования (очереди для heavy load).

5.1. Требования к Telegram mini app (frontend)
---------------------------------------------
- Использовать Telegram WebApp API для интеграции с Telegram (авторизация, WebAppData, кнопки, темы).
- Адаптивный дизайн под Telegram WebView (мобильные и десктопные клиенты).
- Минимальное время загрузки, быстрый отклик интерфейса.
- Поддержка светлой и тёмной темы (автоматически подстраиваться под Telegram).
- Безопасность: не хранить чувствительные данные в localStorage/cookies, использовать только session/in-memory.
- Навигация и UI должны быть максимально простыми и интуитивными для пользователей Telegram.
- Использовать только поддерживаемые Telegram WebView API (ограничения на popups, редиректы, window.open и т.д.).
- Все действия пользователя должны быть подтверждены визуально (toast, loader, disable кнопок).
- Авторизация и идентификация пользователя — только через Telegram WebAppData (никаких сторонних логинов).
- Соответствие UX-гайдлайнам Telegram Mini Apps: крупные кнопки, минимализм, быстрый возврат назад.
- Корректная обработка ошибок и сетевых сбоев (retry, user-friendly сообщения).
- Не использовать сторонние трекеры, аналитику и рекламу, не одобренные Telegram.

6. Особенности и детали
----------------------
- Все операции с БД — асинхронные
- Использовать RORO-подход (Receive an Object, Return an Object)
- Минимизировать глобальные переменные, использовать DI
- Для всех моделей — явное описание nullable/optional полей
- Для заказов — хранить историю статусов, поддерживать soft delete
- Для пользователей — поддерживать роли и права доступа
- Для магазинов — поддерживать связь с владельцем и товарами
- Для отзывов — хранить текст, дату, связь с заказом и пользователем
- Для фронта — использовать fetch/axios для запросов, отображать статусы и ошибки

Нажмите Add Payment Provider.
Выберите нужного провайдера.
Введите merchant credentials (API-ключи, shop id и т.д. — зависит от провайдера).
@BotFather сгенерирует для вас provider_token.
