# GLOSSARY.md

## Продукт и домен
- Пользователь (User) — субъект, взаимодействующий с системой (клиент, курьер, продавец, админ).
- Роли — худБосс, худМанагер, худАдмин, худПрод, худКур, худПотр; определяют права доступа и доступные сценарии.
- Магазин (Shop) — торговая точка продавца с витриной товаров.
- Товар (Product) — позиция в магазине с ценой и доступностью.
- Заказ (Order) — сущность покупки; хранит статусы, суммы, участников и историю.
- Статус заказа — состояние доставки; базовый поток: `ASSIGNED → IN_PROGRESS → DELIVERED → COMPLETED`.
- История статусов — журнал смены статуса заказа (`order_status_history`).
- Отзыв (Review) — оценка 1–5 и комментарий; негативный отзыв — оценка ≤2.
- VIP — признак повышенного приоритета (клиенты/курьеры/продавцы/магазины).
- Переименование магазина — платная операция после первой бесплатной попытки; `shop_name` в заказах — снимок и не обновляется.
- Soft-delete — логическое удаление записи, без физического удаления из БД.

## Доменные события и polling
- Событие (Event) — неизменяемая запись о факте изменения (order.created, order.status_changed и т.д.).
- Domain Event — событие, отражающее бизнес‑смысл изменения.
- Polling — периодический опрос `GET /events?since=<cursor>` для получения изменений.
- Cursor — маркер позиции в ленте событий; соответствует `events.id`.
- Revision — значение курсора, отражающее порядок изменений; возвращается в ответах.

## Telegram WebApp и авторизация
- Telegram WebApp — веб‑приложение внутри клиента Telegram.
- WebView — контейнер, в котором запускается WebApp.
- WebAppData/initData — подписанный набор параметров для авторизации WebApp.
- initDataUnsafe — клиентская версия данных без доверия; использовать только для UI, не для авторизации.
- Data Check String — строка для проверки подписи initData (сортировка ключей, `\n` разделитель).
- auth_date — время формирования initData; проверяется на TTL.
- JWT — токен для авторизации API, передаётся через `Authorization: Bearer`.
- Гладкий WebView UI — ранний `WebApp.ready()`, `WebApp.expand()`, safe‑area inset и стабильная высота viewport.

## Технический стек
- NestJS — серверный фреймворк Node.js с модульной архитектурой и DI.
- Prisma — ORM для TypeScript; схема описывает модели и миграции.
- Prisma Client JS — клиент Prisma; `BigInt` (например `events.id`) сериализуется в JSON как строка на границе API.
- PostgreSQL — основная реляционная БД.
- JSONB — формат для структурированных данных; используется только для `events.payload`.
- Next.js — фреймворк React для SSR/SSG/CSR и маршрутизации в файловой структуре.
- Paraglide.js — генерация функций переводов и i18n.
- Zustand — управление состоянием на фронтенде.
- Docker/Compose — локальная и тестовая инфраструктура.

## API и данные
- REST — команды на создание/изменение/удаление через HTTP.
- RBAC — управление доступом на основе ролей.
- PK/FK — первичный и внешний ключи таблиц.
- Snapshot — снимок значения (например `shop_name` в заказах).
- Idempotency — повторная операция с тем же ключом не меняет результат.
- ETag — версия ресурса на уровне HTTP (опционально).

## Архитектура
- Модульный монолит — монолит с разделением на модули по use‑case.
- Контракт — формализованное соглашение API/событий между компонентами.
- State Machine — модель состояний и переходов для жизненного цикла заказа.
