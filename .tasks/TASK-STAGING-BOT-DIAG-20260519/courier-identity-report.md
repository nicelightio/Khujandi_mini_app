## Lookup Path

Telegram bot actor lookup:

1. `POST /api/v1/telegram/webhook` enters `handleTelegramBotRoutes`.
2. `telegram-bot-runtime.ts` receives `message.from.id` or `callback_query.from.id`.
3. The id is normalized to string.
4. `resolveCourierByTelegramId` calls `deliveryAssignmentModule.controller.getCourierStaffByTelegramUserId(telegramId)`.
5. Controller delegates to `DeliveryAssignmentService.findCourierStaffByTelegramUserId`.
6. Service trims the id and calls `DeliveryAssignmentCourierStaffRepository.findCourierStaffByTelegramUserId`.
7. Prisma adapter reads `User` by unique `telegramId`; dev runtime adapter reads `checkoutPaymentState.users` by `telegramId`.
8. Bot accepts only a row with `role="courier"` and `lifecycle.staffDeactivatedAt === null`.

Current staging row satisfies this identity precondition for `5281851429`.

## Work-Active Path

Staff active and work-active are different states:

- Staff creation creates a courier with `isActive=false`, `acceptingOrdersUntil=null`, `autoOfferEnabled=false`, and `staffDeactivatedAt=null`.
- Bot menu lookup only requires active Staff identity (`staffDeactivatedAt === null`), so a newly created Staff courier can open the `Курьер` menu even before being work-active.
- Pressing the `Выйти на работу` inline button parses `delivery-assignment-courier-availability:start_work:<courierId>` and calls `DeliveryAssignmentService.startCourierWork`.
- `startCourierWork` sets `isActive=true` and `acceptingOrdersUntil=null`, then `toAvailability` reports `active=true` when the courier has no expired cutoff and is not staff-deactivated.
- The auto-offer toggle is separate. Pressing `Автоматически принимать заказы: ON/OFF` calls `setCourierAutoOfferParticipation`; this is needed for broadcast auto-offer eligibility, but not for targeted manual offer identity lookup.

Therefore `Луганский` can become work-active through the bot menu if the deployed staging bot ingress/polling is connected to the real Telegram bot and the Telegram account `5281851429` sends `Курьер` then presses `Выйти на работу`.

## Assignment / Claim Preconditions

Manual offer and claim require more than identity:

- Manual offer checks the target courier exists, is not staff-deactivated, is work-active, and is free.
- Claim checks the offer is pending, target matches the resolved courier when targeted, order is `CREATED|DELAYED`, and the courier is active/free.
- Busy means the courier has an active order in `ASSIGNED`, `PICKED_UP`, `IN_PROGRESS`, or `DELIVERED`.

If `Луганский` exists but has not pressed `Выйти на работу`, manual offer or claim can fail as `COURIER_UNAVAILABLE`.

## Failure Modes Specific To Луганский

1. Reset/seed wipes the row.
   - Seed recreates `courier-7` / `70007`, not `5281851429`.
   - Fix/check: after reset/seed, list or create Staff courier again and record the returned `courierUserId`.

2. Telegram id mismatch.
   - Bot uses `from.id`, not username/nickname/chat title.
   - If the human Telegram account is not `5281851429`, lookup fails as `COURIER_NOT_FOUND`.

3. Staff-deactivated courier.
   - Staff list default hides deactivated rows.
   - Bot lookup rejects deactivated staff as `COURIER_NOT_FOUND`/403.
   - Boss-only archive/reactivation is needed for deactivated rows.

4. Active Staff but not work-active.
   - Staff `activeStatus=active` only means not soft-deleted.
   - Work-active requires `Выйти на работу` through bot or equivalent service call.
   - Manual offer and claim require work-active/free.

5. Auto-offer off.
   - Staff creation defaults `autoOfferEnabled=false`.
   - Broadcast auto-offer ignores the courier until the bot toggle is ON.
   - Targeted manual offer does not require auto-offer ON, but still requires active/free.

6. Busy courier.
   - Existing `ASSIGNED`, `PICKED_UP`, `IN_PROGRESS`, or `DELIVERED` order blocks new claim/offer eligibility.

7. Bot transport not connected.
   - Health route does not expose polling/webhook status.
   - Webhook requires `TELEGRAM_WEBHOOK_SECRET` when a real Telegram bot token is configured.
   - Polling requires `TELEGRAM_BOT_POLLING=TRUE` and a real-looking Telegram token.
   - If polling/webhook is not wired, Staff identity can be correct but the human sees no interactive bot response.

8. Callback actor mismatch.
   - Claim/availability callback payload contains courier id.
   - Runtime rejects callbacks when `callback_query.from.id` resolves to a different courier than the payload courier id.
